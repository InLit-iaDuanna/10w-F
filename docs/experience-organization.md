# 经验怎样分类、怎样调用

2026-09-08：在经验服务完成后，按用户要求重新设计经验页面并研究 GitHub 项目的记忆组织方式。

## 调研依据

| 项目与一手来源 | 实际做法 | 对本工作台的启发 |
| --- | --- | --- |
| [Hermes Skills](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md) | 分类与标签描述方法；先列索引，再按需加载正文和引用；方法说明含适用条件、步骤、陷阱和验证 | 浏览时先呈现主题与摘要，打开后阅读方法；不把所有表单和来源堆在首页 |
| [Letta Memory Architecture](https://github.com/letta-ai/skills/blob/main/letta/letta-api-client/memory-architecture.md) | 区分常驻核心记忆和按需查询的历史/知识；归档支持类别、主题等元数据 | 分类协助查找，经验正文按需提供；技术知识不需要全量进入每次对话 |
| [Hindsight Mental Models](https://github.com/vectorize-io/hindsight/blob/main/skills/hindsight-docs/references/developer/api/mental-models.md) | 整理后的总结与观察、原始事实分层，保留来源；标签同时影响筛选和检索，过严的标签交集可能遗漏材料 | 经验与证据分开呈现；保留纠正和修订；一个主题不能成为排除相关跨领域经验的唯一条件 |

以上是产品组织与检索方式的借鉴，没有复制第三方实现或引入其框架。Hermes 的 Skill 存储方式不属于本次工作台改动。

## 分类规则

下面六个主题是根据这 26 条工作台经验选择的产品分类，不是照搬某个项目的目录。主题回答“正在解决哪类问题”；工具标签回答“涉及什么技术”。证据状态回答“结论有什么依据”，不与主题混在一起。

| 维度 | 内容 | 例子 |
| --- | --- | --- |
| 主题，可多选 1–3 个 | 构建与交付、体感与交互、场景与动画、资产与性能、运行与播放、工程与协作 | 包体压缩同时属于资产性能、构建交付、运行播放 |
| 工具与技术标签 | 沿用领域标签和平台标签 | Xcode、Blender、Unity、iOS、四元数 |
| 内容种类 | 操作方法、故障案例、项目事实 | 方向锁的用户纠正属于故障案例 |
| 证据状态 | 待验证、有支持证据、有反证、已被替代 | 虚拟地面案例保留反证，不包装成成功方法 |
| 范围 | 当前项目、本地共享 | 具体项目状态留在原项目，通用方法可以共享 |
| 启用状态 | 开启或停用 | 停用独立于证据状态，也不会删除历史 |

一条经验只有一个稳定 ID；出现在两个主题里是同一条记录的两个浏览入口，修改不会产生两份副本。首批 26 条经验有 34 个主题归属，因此各主题计数相加大于条目总数。

首次资料整理的分类数：构建与交付 7、体感与交互 8、场景与动画 6、资产与性能 4、运行与播放 4、工程与协作 5。无明确归属时保持“未分类”，避免自动造出大量零散小目录。

新经验在原有学习请求中同时提出分类，不增加额外分类模型调用。用户可以在编辑时纠正主题；分类修改同样检查版本并保留修订历史。旧版种子若没有主题字段，只补充主题并产生一条新修订，保留用户已修改的正文、证据和停用状态；用户主动清空的分类不会被启动过程补回。

## 对人的使用方式

经验入口分为“经验库”“学习动态”“设置”。默认是可读的经验库：选主题或搜索，结合类型、状态和工具筛选，再打开条目。先看内容和适用条件；需要纠正时才进入编辑。来源与修订记录按需展开。学习批次、失败原因和调用预算有独立位置，不占据浏览的主要空间。

## 对 Agent 的使用方式

无需每次由人手工挑经验。服务按当前问题，在当前项目与可共享条目中检索；主题名称加入已有全文索引，召回结果携带主题、适用条件、证据和准确版本。主题有助于检索和解释来源，但不会使一个主题的全部经验自动进入上下文。停用和被替代条目不参与推荐，相关反证一起提供。

Agent 依据本轮任务决定是否采用；界面只记录实际提供过的版本，不把提供次数当作成功次数，也不自动把“有历史证据”升级成“当前项目已验证”。当前分类是产品维护的六个稳定主题，不会由模型任意扩展目录。
