# 对话中的学习与记忆

项目记忆、经验使用与学习结果现在跟随对话和制作任务展示。没有新增常驻栏或侧栏；「经验」仍是集中管理入口。

## 日常使用

- 用户消息下的「记住」可保存项目事实、执行约束和已确认决定；保存失败保留草稿，重试不会重复创建条目。
- 「本次依据」展示该次请求真正得到的项目决定、经验及版本。没有相关内容不占位；读取失败单独显示原因。这里的旧版本不会因为之后的纠正而变化。
- 在消息内点「纠正此条」读取最新版本后编辑；保存生成「修改前 / 已保存」记录。撤销生成新修订，保留历史。
- 自然语言中的明确记忆请求由当前前台回合提出结构化更新。只能引用本轮已保存用户消息；含糊内容保留为候选，可在消息内查看、修改并确认。附加提案错误不会使正常策划回复一起失败。
- 新增记录整理完成后，「本次沉淀」更新到原结果消息或任务下，不追加打断对话的新消息。预算等待、失败、暂停均显示实际状态。
- 管理入口分为「项目记忆 / 通用经验 / 学习动态」，设置单独打开。通用经验默认显示共享条目，可切换范围查看项目内方法与案例；项目私有内容不会因此改成共享。

## 项目决定与通用经验

已确认初版方向来自 Design Room 的现有状态。记忆界面引用其版本，修改和撤销调用原来的项目命令，不另建可编辑副本。工程架构和目标平台保持只读，通过原制作流程处理。补充事实、约束保存在项目范围，方法与故障可以保持项目范围或提炼后共享。

每次实际请求重新读取有效记忆。普通对话使用消息 ID，策划使用准确的回复消息 ID，类型化调用及原生制作使用各自调用标识；原生恢复使用实际运行 ID，不复用旧运行快照。同任务续改保留初始目标与每次已接受请求的独立来源。

制作准备继续选择资产、经验和技能。经验正文由同一个提供接口限量记录，历史准备正文不会重复进入新请求。未配置推荐模型时，检索命中的经验也通过同一接口提供，不额外调用模型。项目决定与经验合计最多 8 项、12,000 字符；方法和关联反证一同计入上限，无法同时提供时略去整组并标明范围。

读取、执行引用、验证是三类记录。运行时只有解析到已保存动作或验证来源，并核对实际提供版本，才能记录引用或验证；未知结果保持未知，构建通过不等同于设备行为通过。

## 公开接口

保留现有 `/api/experience` 条目、版本、设置、预算和学习接口，增加：

| 接口 | 行为 |
| --- | --- |
| `GET /api/experience/project-memory?project_id=…` | 聚合原项目决定与补充记忆 |
| `POST /api/experience/memories` | 根据服务端核对的 `source_id` 保存或纠正；目标修订带 `expected_revision`；`request_id` 用于幂等重试 |
| `GET /api/experience/activity?project_id=…&origin_key=…` | 精确查询原消息或任务的变更、批次与待处理状态 |
| `POST /api/experience/events/{id}/undo` | 按当前修订撤销，生成新的历史记录 |
| `GET /api/experience/uses?project_id=…&use_key=…&exact=true` | 读取对应请求实际获得的快照；任务可显式查询自己的调用前缀 |

候选确认使用 `resolves_event_id` 关联原事件，原候选显示已处理。`persisted=false` 表示存储失败，不能显示已保存。所属模块通过公开来源解析、项目读取和修改回调接入。运行证据使用 `record_usage_evidence` 公共服务接口，浏览器不能伪造工具验证。

OpenAPI 与 TypeScript 类型由 Pydantic 生成。关闭自动学习仍可主动保存和纠正；关闭经验读取不删除历史。现有独立预算、脱敏、来源游标、种子幂等导入保持有效；没有回溯旧历史、训练参数或修改 Skill。

## 验证

定向测试结果：69 项后端测试、9 项前端组件测试通过；停用条目的管理可见性修正后，相关 9 项后端测试再次通过。

本轮使用临时 SQLite、隔离文件夹与明确标注的模型响应夹具，未调用真实模型、Blender、Unity、设备安装或发布。

- 后端验证包含来源归属、即时保存与下一请求召回、跨项目共享与隔离、并发修订、重复请求、重启、候选确认、撤销、批次与预算、未知证据、上下文限量与成组反证。
- 通过真实 API 组合验证了补充约束的保存 → 纠正 → 再次读取 → 撤销，也验证了已确认方向修改和撤销确实回到原策划状态。
- 使用注入的模型响应验证普通对话、策划、类型化和原生请求接入；后台学习结果关联原回复，另一项目召回修订前后版本保持可追溯。
- 前端定向检查覆盖空态不占位、失败保留草稿、候选确认、幂等重试、任务终态刷新、项目案例范围筛选及既有编辑保护。
- 实际工作台页面在桌面与 390px 宽窗口检查消息内展开、纠正、来源跳转、撤销，以及管理入口的搜索、停用和恢复。截图位于 `output/playwright/memory-inline-desktop.png`、`output/playwright/memory-inline-mobile.png`、`output/playwright/memory-panel-mobile.png`。

## Limitations

- 本轮模型行为验证为注入测试；没有把它标为真实模型采用或设备验证。
- 项目决定与记忆事件由各自模块事务保存。若进程恰好在项目决定提交后、事件保存前退出，原决定仍是唯一有效状态，但可能缺少对应内联事件。
- 经验组件定向类型检查通过；包含整个工作台依赖的检查仍存在既有 Unity 请求类型问题。仓库完整模块导入检查仍有已有跨模块依赖及动态导入诊断；生成目录使用现有生成器的清单/依赖图校验模式同步，未宣称完整导入检查通过。
- 窄屏全局顶栏仍有原有按钮拥挤现象；本次未重做工作台外壳。Dockview 的既有许可证提示不属于记忆执行错误。
