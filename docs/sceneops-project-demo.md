# SceneOps 项目初版与内容回流

## 用户路径

1. 用户在 Journey 填写核心体验、视角与风格、目标平台、技术架构和简化范围。
2. 确认方向只保存方向并创建游戏工程，不写入 Demo 内容，也不启动任务。
3. “发起初版制作”准备新的 `project-demo-agent` 授权卡，显示登记工作区、可用内容／源码工具和整个任务的累计预算。用户确认后，真实制作模型按方向逐步选择动作；旧 `project-demo` 仍保留为零模型的钥匙门夹具入口。
4. 工作台可修改门配方、单个场景实例的变换和 `KeyDoor` 行为参数。保存配方会创建新资产版本，并明确列出更新到该版本的引用实例。
5. 内容面板的“更新 Demo”复用原项目任务并程序化物化、检查和构建。对话中的“继续修改同一 Demo”给同一个 `project-demo-agent` 增加新目标，由模型继续编辑真实源；请求幂等键与方向身份分开记录。两者都沿用原工作区、授权期限和累计预算。最新请求构建成功后才切换试玩；失败时继续提供上一个成功候选。
6. 重开项目后，从 SQLite 记录恢复工作区、任务、场景、资产版本和候选引用。运行时拾取、开门等试玩状态不写回场景源。

详细策划、架构推荐和四张制作卡仍保留为高级路径；原卡片任务继续使用卡片分支与工作树。

## 权威源与派生物

| 内容 | 权威源 | 稳定身份与版本 | 运行使用方式 |
| --- | --- | --- | --- |
| 项目执行归属 | Project Intake 登记的项目 Demo 工作区 | `project_id` + `workspace_id` | 任务、授权、运行记录、候选和预览均校验该组合 |
| 程序化门 | Asset Library 的资产条目与 `DoorRecipe` 版本 | 共享 `asset_id`、不可变 `asset_version_id`、递增版本 | 宽、高、厚度和材质生成网格与碰撞尺寸 |
| 场景实例 | World Composer 场景版本 | 稳定实例 `id`、递增 `scene_version` | 位置、旋转、缩放逐实例读取；改单个实例不影响其他实例 |
| 门行为 | 场景实例上的 `KeyDoor@1` | 稳定 `behavior_instance_id` | 对象／组件读取行为实例；Miniplex 系统查询同一份组件数据 |
| 新玩法行为 | 聚焦的普通项目源码及其中的公开参数 | 源码路径与任务写入记录 | 按所选架构接入现有运行循环；后续目标继续修改同一来源 |
| 构建输入 | 选定场景版本及其引用的资产版本 | 候选记录保存源码、场景和资产版本引用 | 物化到工程内的 `.sceneops/demo-content.json` 与 `src/game/sceneops-demo-content.ts` |
| 试玩 | 最新成功且仍属最新请求的构建候选 | 工作区内单调候选序号 | 每次构建保留独立 `dist`；失败不替换当前可玩候选 |

`sceneops-demo-content.ts`、`.sceneops/demo-content.json`、测试适配器、运行网格、碰撞几何和构建目录都是派生输入或产物，不能作为 Agent 编辑源。物化只替换两份内容派生文件，保留模型编写的行为模块；内容只含项目内相对引用，不依赖其他工作区的绝对路径。

## 公共服务连接

- Asset Library 通过门配方定义和资产 recipe-version 接口公开参数类型、单位、默认值与范围。
- World Composer 通过 `KeyDoor` 定义、实例行为更新和共享资产版本换绑接口连接面板与任务执行。
- Agent Runtime 只调用上述服务、登记工作区的精确前文源码写入和 Project Intake 的公开物化服务。`project-demo-agent` 复用现有 Agent 循环、历史引用、授权与动作记录；模型不能提供 Shell、任意目录、端口或数据库操作。
- `Demo Composer` 与 `Editable Content` 的完整正文只在 `project-demo-agent` 决策请求中装配，并把资源路径与版本写入 Harness 调用日志。原 Gameplay、Debug、QA 技能仍按当前阶段选择。
- 普通物化不创建资产、实例或行为。确定性钥匙门只由旧 `project-demo` 明确初始化，因此删除内容后再次物化不会把夹具补回。
- 构建候选记录关联项目、工作区、任务、源码信息、场景版本、资产版本和构建运行。

## Limitations

真实模型验收只覆盖 Three.js 对象／组件工程；对象／组件和 Miniplex ECS 的共享内容适配器均执行了确定性回归与真实 TypeScript/Vite 构建。浏览器观察证明页面、画布和错误状态，具体玩法仍须使用对应的受控输入或人工试玩单独验证。

本批不接入付费素材、Blender 往返、通用行为编辑器、完整 D4 工作台、所有游戏类型或所有引擎。当前领域内容工具仍以程序化门与 `KeyDoor` 为首批能力；其他玩法通过普通项目源码实现。这次通过证明两个具体目标可由真实模型改变实际作品并继续修改，不代表任意 idea 都能自动制作。
