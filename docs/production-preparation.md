# 按任务选择资产、经验与制作方式

专业制作请求现在会先生成一份任务级“制作准备”。它读取用户要求、已确认方向、目标平台、当前工程摘要和本次已有能力，从公开候选目录中选择资产、经验与制作技能，然后把所选详情交给主制作 Agent。普通聊天、手动编辑和后台经验学习不进入这条流程。

## 请求边界

| 入口 | 制作类型 | 可选材料与执行边界 |
| --- | --- | --- |
| 首版游戏、游戏修改 | `game_create` / `game_modify` | 可选择已授权的内置素材、当前项目资产、经验和游戏制作技能；原生与类型化 Agent 复用同一结果 |
| 独立建模 | `modeling` | 只提供当前执行器能够完成的复用、导入或固定原语能力 |
| 场景搭建 | `scene` | 先把获准采用的内置素材登记为真实项目资产，再向摆放模型提供项目资产 ID |
| 专业策划 | `planning` | 资源只作为可行性依据，不复制文件或修改工程 |
| 导出 | `export` | 只提供目标平台经验和现有导出能力，平台必需指令继续固定保留 |

同一个 `project_id + request_key` 最多发起一次推荐调用。主 Agent 的多步执行读取持久化结果；新用户要求使用新的请求键。请求键复用但正文发生变化会被拒绝，避免把旧选择误用于新目标。

## 候选和上下文

候选只由模块公开接口提供：内置资产目录、当前项目已登记资产、当前项目及共享有效经验、产品已有技能与本次能力。其他项目私有资产、停用或已取代的经验、平台不匹配条目和缺少执行能力的条目会在调用前过滤。

目录不超过 24,000 字符时完整提供。超过预算时，先为资产、经验、技能和能力保留按相关性排序的完整条目，再用全局相关性填满剩余空间；条目不会被截断。经验排序复用经验模块现有的中英文全文检索，目录只放适用范围和元数据。推荐完成后才按 ID 与修订读取所选经验全文。

推荐器最多选择 6 条经验、4 项技能；资产按实际用途选择，可以全部为空。返回的资产版本、经验修订、技能版本和能力 ID 必须与目录完全一致。有争议的经验必须引用目录提供的反例，否则整次推荐记为无效。

主 Agent 只收到选择结果和所选详情。类型化任务的技能由受控技能加载器读取，因此不会在准备上下文中重复塞入技能全文；原生 CLI 任务直接获得所选技能详情。旧的关键词经验批量注入已从专业制作链移除；普通聊天的经验阅读开关和历史记录保持兼容。

## 模型与失败处理

“模型与提供方设置”中的“制作推荐模型”独立保存提供方和模型。它复用对应提供方的现有连接和凭据，通过调用开始时的配置快照运行，不修改主模型。

每个请求最多一次调用，最长 30 秒，无自动重试或换模型。模型、耗时、Token、费用和状态单独记录并并入入口已有的用量记录。费用未知时保持未知。未配置、预算不足、超时、取消或结构无效时，主制作继续读取候选目录和工程事实自行选择；系统不会恢复批量经验注入，也不会把失败记录显示成推荐成功。

## 资产落地与证据

游戏项目只复制推荐选中的内置素材及共享依赖，原整包接口继续供旧任务使用。目标文件已存在时保留原文件。所选目录写入真实项目工作区，主 Agent 从其中的 URL、尺寸、动画和素材说明加载。

场景入口使用原有采用服务把内置素材登记进当前项目，然后刷新资产库并向摆放模型提供真实项目资产 ID。策划不执行采用。缺少权限或能力会记录为缺口，不会切换引擎或安装新工具。

记录明确区分以下状态：

- **推荐**：选择模型返回了该条目。
- **已提供**：详情或项目目录已交给主 Agent。
- **已复制／已保留**：文件落入工作区，或目标处已有用户文件而被保留。
- **实际引用**：工程源码出现所选素材的真实 URL 或文件名；素材目录自身不参与扫描。
- **运行验证**：工程检查、构建和预览的结果单独显示。工程通过仍不自动证明素材在画面中正确加载，视觉验证保持 `not_verified`，直到有实际游测证据。

模型自述和文件复制都不会写成“已验证经验”。主 Agent 可以依据实际文件和运行结果调整选择，调整记录留在原制作任务中。
系统会把“所选资产提供失败”和“源码未观察到所选资产引用”列入“执行调整与缺口”；后者只是待核查证据，不会被误写成已确定未使用。

## 效果对照

使用 `scripts/evaluate-production-preparation.py` 检查对照结果。输入包含“一屏收集”“角色生存”“现有游戏修改”三个案例，每个案例的旧流程和新流程至少各运行两次，且主模型与总预算相同。

```sh
node scripts/python.mjs scripts/evaluate-production-preparation.py results.json --output report.md
```

每次运行需要记录首版可玩性、所选与实际引用资产、风格和尺度一致性、修改保留、耗时、Token、用户介入次数，以及可核查的质量观察。检查器要求新流程在每个案例中都有实际资产引用和具体质量收益；推荐文字合理或复制数量增加不能单独通过验收。

## Limitations

候选仍基于目录元数据与文字检索，没有视觉检索或向量数据库。真实 A/B 需要可用的独立推荐模型、相同主模型和隔离的可比工程；仓库测试只验证选择、执行边界、资产落地和记录语义，不替代六组真实生成与试玩。
