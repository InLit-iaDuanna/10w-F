# 游戏界面

界面从同一玩法状态读取目标、进度与结束条件；不要维护第二套规则。开始、暂停及重开必须作用于真实游戏状态，并清理原有监听和动画。

按任务的视觉参考统一字体层级、间距与反馈。宽窄窗口检查遮挡、溢出、焦点、可点击区域以及 canvas 与叠层事件命中。仅在用户范围包含时增加触控或键盘导航。

普通 UI 源码通过原生 CLI 修改；用 SceneOps 浏览器观察与实际输入验证开始、核心交互、结束和重开。预览地址、非空截图或构建通过均不能代替交互验收。

## 专业配置与声音回流

用 `production.document.read` 读取当前项目 `ui-audio-vfx` 的已保存布局、事件、混音和声音源引用。保留文档版本与目标对象身份；Mock 示例不能当作已发布资产或实际游戏内容。声音源 `audio_source.path` 指向项目登记附件，使用该真实文件制作运行资产，保留来源关系，不用测试音替代用户音效。

把 UI 与声音接到同一游戏事件和状态，验证事件触发、暂停、静音、重开及监听清理。浏览器音频须在真实用户操作后解锁；不得反复创建 AudioContext。确认所选声音实际播放、音量与并发策略符合要求后，再报告声音流程已验证。
