# 结果核验

## 适用范围

用户要求检查，或源码修改后进入已有授权允许的验证阶段。只覆盖相关行为和受影响的共享路径，不把小改动扩成发布或全量美术流程。

## 输入事实

读取当前目标、实际文件修改、操作结果及其项目/worktree。检查是否有后续源码变化、source_stale 和未完成操作；复用仍适用的结果。

## 工作方法

使用已连接 SceneOps MCP 的 code.project.status/check/build 领域工具，让工作台接回真实运行记录；原生 CLI 可按授权编辑普通源码并执行本地诊断，依赖准备服从当前安装授权。没有执行工具时分析已有记录，列出未执行项。
分别判断源码写入、类型检查、构建、预览启动、浏览器加载、真实输入行为和视觉观察。预览 URL 或 PNG 路径不证明看过画面；直接设置完成状态不证明玩家能通关。
现有 code.browser.interact 的 movement/collection 检查依赖旧测试协议，current-input 也要求既有位置读回；它不是任意游戏的通用验收。原生工程没有对应协议时如实报告未验证，不为通过旧检查重写玩法或加入虚构读回。code.browser.observe 可独立检查页面加载。
冷却修改应验证重复触发、再次可用、暂停和重开，同时保留旧移动/冲刺；测试需经过实际输入路径才可称行为验证。没有浏览器或输入工具时报告此项未执行。
UI 检查实际状态驱动、文字遮挡和目标视口；移动端、动画、音频仅在用户范围涉及且具备执行条件时验证。极简、静音、无失败、桌面限定均为有效设计，不强制 AAA 阈值。

## 常见失败

把 dev 通过当发布构建通过；截图非空当好玩；旧结果当当前源码证明；读取日志当视觉观察；删掉失败项或放宽检查来交付。

## 完成依据

按实际记录报告通过、失败、未执行或无法判断的范围，引用对应运行/产物。没有观察不得编造截图结论；颜色熵、边缘和几何统计不能替代视觉判断。问题回到原任务修复后复查，不创建新的验证数据库或额外授权流程。

## 原生制作与领域回流

普通源码使用 CLI 原生读写能力；资产版本、实例变换及共享引用使用 SceneOps MCP 提供的领域工具。先读取当前版本，再带 expected_version 更新；冲突时重读并按用户意图修订。托管内容修改后调用 code.demo_content.materialize，并让实际游戏读取其生成的内容模块。不要直接编辑托管清单或虚构逐动作 JSON 调用。
