# 应用发布

先区分用户要求的是本地试玩包、发布准备、测试渠道上传还是正式公开发布。只做本地包不需要商店账号，不创建云构建账号或上传源码。用户明确要求仅准备或不要上传时，不写入商店，包括上传 metadata/截图/changelog 和创建 draft release；只产出本地材料与待执行配置。继续使用项目已经配置的发布工具；没有 Fastlane 的项目仅在明确需要其能力时引入。

准备可审阅的具体交付：产物与来源版本、应用标识、目标账号/应用/渠道、版本号、发布说明、图片和测试证据。核对签名与现有应用一致、版本号满足目标平台规则。密钥通过现有凭据通道引用，不写进命令日志、聊天、仓库或安装包。

需要 Fastlane 时检查 Gemfile/Gemfile.lock、Fastfile 与目标 action 帮助，使用项目锁定版本（通常 bundle exec fastlane）。官方 actions 文档是参数依据；上游示例不是当前账号、渠道或范围授权。

Google Play：核对现有应用、服务账号访问与选定 track；明确指定 APK/AAB、track 和 release_status。metadata、截图与 changelog 分别控制，不因工具默认值覆盖现有商店内容。上传不等于审核通过，draft 不等于公开发布，测试渠道不等于 production。首次应用登记或权限缺失需按实际平台流程处理。

macOS/Windows：本地 ZIP、Developer ID/Authenticode 签名、公证、商店发行是不同步骤。确认用户目标才获取对应证书与发布入口；签名能力只读发现不代表可以使用所有账号发布。GitHub Release 等公共下载也属于对外发布，要核对仓库、tag、资产和可见性。

在执行已获明确授权的目标上传前完成可验证准备；缺少发布目的地、必要账号访问或明确发布授权时停在具体缺项，保留已完成本地产物。不要额外重复已有授权。遇到付款、许可、登录/管理员系统交互，由实际电脑工具的权限要求决定交接；不得用自动点击绕过安全确认。

发布后读取目标平台返回的版本、渠道和状态，记录响应或可访问链接；失败只重试未完成项，已上传成功不盲目重复提交。完整说明哪些步骤完成、哪些仍在审核。

使用 [Fastlane 官方发布资料](references/sources.md) 核对参数和覆盖行为。
