# 原生 CLI 制作

SceneOps 先对齐方向，再交给 Codex 或 CodeBuddy 在登记工作区制作。普通源码使用原生文件工具；资产、场景和共享引用通过当前任务的 SceneOps 工具修改。历史动作任务保留，新制作不再走逐动作 JSON 决策入口。

## 用户流程

1. 确认方向、架构和资料，选择已配置的 Codex 或 CodeBuddy。
2. 查看并修改制作简报，核对必做、边界、素材和可自由发挥细节。简报和执行权限在同一处确认；完整权限策略也不会跳过简报确认。
3. 点击「确认简报并开始制作」。普通策略使用当前任务范围，完整权限使用明确选定的完整权限。登记工作目录不是操作系统沙箱。
4. 查看执行事件、实际文件和构建结果。制作结束后，工作台提供实际源码、资产与实例入口；源码有变化时显示尚未构建。构建失败保留之前的成功候选。
5. 发送「移动太慢」等新增要求，沿用准确的原生会话。普通续改不再重复确认初版简报；改变简报会产生新版本，需要确认该版本。

## 接口与来源

- `GET /api/agent/tasks/{id}/creation-brief` 读取简报；`PUT` 使用 `expected_version` 和 `content` 保存。旧版本冲突不会覆盖当前简报。
- 准备任务使用 `native_production=true`、`execution_mode=agent-full-access`，权限由独立的 `permission_mode=scoped|full` 指定。执行器仅支持 `codexcli`、`codebuddycli`。
- 授权提交 `creation_brief_version`。查询、事件、取消、内容编辑和续改沿用现有任务接口；前端网络类型从后端模型生成。
- D4 源码登记属于项目和工作区，基于真实文件维护稳定 ID、版本和来源，不伪造 `code.file.write`。来源可为普通工作区、真实类型化写入或原生制作任务。
- 删除保留内部登记，移除失效编辑入口。明确确认的重命名保留 ID，不按相似文本猜测。源码浏览沿用 256 文件、每文件 64 KiB 的限制；达到上限时显示提示，不把未列出的文件判为删除。

## 中断与故障

权限不足显示具体原因，不自动升级；同一工程不能同时执行两个制作任务或与手动写入并发。取消保留已发生修改和事件。会话 ID 缺失、服务中断或未知结果需要核查，不自动重放，也不恢复「最近会话」代替准确身份。CLI 启动次数与内部模型调用次数分别记录。

简报加载失败可重新读取；保存或授权失败保留编辑内容。原生制作不显示历史逐动作预算续期提示。旧任务继续按原授权规则处理。

## 验证状态

新增本地用例覆盖准备与确认分离、完整／当前任务范围、匹配会话续改、不支持的执行器拒绝、授权失败保留简报，以及真实源码版本、删除、重建、明确重命名和路径隔离。具体执行结果以本轮主代理测试报告为准。

真实制作验收只使用 CodeBuddy 当前配置和额度，以「风暴灯塔岛」检查移动、点灯、返回安全区、冷暖视觉反馈，以及「移动太慢」续改和工作台内容回流。本轮真实初版、同会话提速和工作台回流已完成；具体通过、失败与未验证范围见 [验收报告](../../../NATIVE_CLI_PRODUCTION_ACCEPTANCE.md)。Codex 仅作为本地适配验证，未经本轮真实制作验收；构建通过不等于玩法与画面通过。

## 内容接口补充

`POST /{task_id}/project-demo/content` 对共享文件资产可提交 `asset_version`，与配方编辑互斥；同时校验资产当前版本和场景版本，更新引用后仍需重建。`GET /{task_id}/project-demo/source-registrations` 返回包含删除记录的源码登记；`POST /{task_id}/project-demo/source-rename` 接收原 ID、expected_version、新路径，以及已登记目标的 expected_target_version，显式确认实际改名并保留身份，不移动文件或猜测相似度。

CodeBuddy 常规权限使用 acceptEdits，精确允许当前 SceneOps MCP 工具；没有广泛授权延迟包装器。原生游戏缺少旧浏览器交互协议时，该工具的失败应保留，使用实际支持的独立输入验证并单独记录。

## 从初版整理制作卡片

公开 `production_snapshot(service, project_id)` 供组合层向策划模块提供当前源码身份、版本、近期制作目标及资产/实例数量。无源码、无原生会话、活动制作或超过整项目上下文读取范围时明确报错。它不执行模型或改写游戏源码；源码登记复用 workspace_sources。

`ContinueProjectDemoRequest.planning_card_id` 可选。续改从服务器的 production_card_context 回调读取已确认策划、当前卡片对话和实际关联源码，核对 workspace_id 后继承原 session_id 与原授权。任务保存 planning_card_id 和 production_card_context，UI 按卡片与对话过滤记录。仍在同一工程交付候选，不创建卡片分支，不把代码生成的网格自动转成托管资产。卡片上下文是修改目标，不是新的权限边界。
