# 卡片架构与源码精修

2026-09-08

在制作卡片标题栏右侧点击「源码」图标按钮，打开独立的大尺寸「架构与源码」工作区，默认读取 `src/main.ts`（没有时读取第一个文件）。按登记 worktree 的实际目录浏览文件。对象／组件与 ECS 工程沿用自身目录；目录与文件都是当前源码，不将制作卡片猜测成代码模块。可选择整个目录分区，或逐个勾选文件。

点击文件可查看和手动编辑；保存使用源码精确前文、已有任务授权、Harness ChangeSet、写入回读及构建失效机制，不另造文件写入器。折叠面板保留草稿，存在未保存内容时阻止切换文件和返回卡片列表。文件冲突保留草稿，用户可复制合并；「放弃本次编辑」恢复读入内容，然后「重新读取」获得最新文件。

输入局部精修要求，准备并确认所列文件范围后，AI 使用 `typed-tools`，可读取工程源码作为上下文，只能写入授权的文件。列表保存在 `AuthorizationCard.source_write_paths` 与 `TaskGrant.source_write_paths`，执行前校验一致性，`CodeWorkspace` 在暂存和实际写入时检查精确路径。模型上下文也携带该范围。选区是已有文件集合，不授权整个目录及未来新增文件。

「修改后检查、构建并更新试玩」同时作用于手动保存和 AI 精修，复用既有工程运行能力与卡片右侧预览。依赖需预先准备；文件精修不授权安装依赖、生成测试源码、写入素材或原生 Shell。源码已保存但后续构建失败时，界面如实报告分阶段结果，不显示试玩已更新。

## 公共接口

所有路径位于 `/api/agent/projects/{project_id}/cards/{card_id}/source`：

- `GET /`：架构说明、登记分支、按目录分区的源码列表和截断状态。
- `GET /file?path=...`：有界 UTF-8 文件内容。
- `POST /file`：`path / expected_content / content / allow_game_execution`；执行用户指定的保存，返回任务记录。手动保存使用固定动作，不请求模型。

`POST /api/agent/tasks` 的可选 `source_write_paths` 仅支持受控卡片任务，1–32 个已有普通源码路径。缺省为原有授权语义，不缩减或扩大旧任务权限。派生运行输入仅可查看。

公开组件 `CardSourceEditor` 由 Shell 通过 Design Room 的 `development.renderSourceEditor` 组合，文件 API 与生成网络类型归运行模块所有。

## 验证

- 后端最小烟测 `test_source_editor_smoke.py`：隔离真实 ECS Git worktree 的目录读取、手动保存、旧前文拒绝、原生模式拒绝、越界写入不落盘、授权文件写入回读、持久授权与模型零调用。
- 前端最小烟测 `card-source-editor.test.tsx`：文件选择、折叠后保留草稿、保存冲突保留草稿、正确文件范围及受控模式、确认后才开始。
- 新组件、客户端和两个宿主入口的定向 TypeScript 诊断检查；非全仓检查。

## Limitations

当前只编辑已有文件，不新增／迁移架构、不解析任意源码的语义依赖图。每文件最多 64 KiB，列表沿用 256 文件／目录读取上限，一次范围最多 32 个文件；超出时显示提示。需要关联文件修改时，由用户重新选择范围。

本轮未调用真实模型，未运行完整构建、浏览器端到端或游戏试玩。可选保存后构建链复用既有运行时，本轮未实际启动游戏构建。不能将定向烟测表述为全部生产链验收。
