# Concept Lab module guidance

## Ownership

This module owns concept specifications, moodboards, style-bible views, concept
references, image-variant review, style-evidence assessments, review decisions,
and compilation of an approved concept into an `AssetSpecDraft`.

It does not own Project Bible data, task planning, image-provider SDKs, artifact
storage, or final 3D asset production and publication.

## Invariants

- Project Bible, feature, and task relationships are stable IDs only.
- Imported and generated images always retain provenance, license permission,
  and an honest execution mode.
- Style checks report reviewable evidence and confidence; they never assert
  objective artistic truth.
- Rejection is an append-only review decision. Rejected variants are retained.
- AI-authored spec edits use an approved Concept ChangeSet before versioning.
- `AssetSpecDraft` is a draft handoff. This module never publishes an asset.

## Module commands

```sh
uv run --project modules/concept-lab/backend --extra test pytest -q
npm --prefix modules/concept-lab/frontend test
uv run --project modules/concept-lab/backend python modules/concept-lab/scripts/export_contracts.py --check
```

## Generated files

Files under `contracts/events/` and `contracts/manifests/` are generated by
`scripts/export_contracts.py`. Change the Pydantic source models, then regenerate.

## Integration boundary

Only `frontend/src/index.ts` and `backend/src/concept_lab/__init__.py` are public.
Do not import another module's internal files.
