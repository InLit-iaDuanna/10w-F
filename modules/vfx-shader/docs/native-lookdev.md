# Lumaform 原生材质整合交付记录

实现位置：SceneOps Forge 的 `vfx-shader` 模块，编辑器 `lookdev.material`，名称“材质与灯光”。

## 已实现

- Dockview 原生标签、资产和环境实例入口、游戏内容工具分组、命令搜索。公共 `lookdev.open` 按项目、资产版本和实例聚焦已有面板。
- 使用宿主字体、主题变量、按钮与输入样式；顶部对象/材质槽、历史、对比和保存，窄面板上下排布，导出菜单。没有导入原应用全局 CSS、首页、独立聊天或模型设置。
- 工作台相关 Three.js 统一 `0.185.1`，类型 `0.185.4`。WebGPU 编辑器按需加载、隐藏停绘、关闭释放资源，普通预览保留 WebGL。
- PBR、程序化图案、结构化 Shader 图及命名参数、灯光、环境、视图、前后对比、撤销重做。共享材质在局部修改前隔离；本地事务仅在候选编译、实际绘制与 GPU 错误域校验完成后提交。
- 主对话固定项目、资产版本、对象、材质槽和灯光作用域；使用现有提供方与模型服务。取消、手动修改、销毁使旧提案失效。材质回合存入原主对话，重开可读，失败/取消/拒绝/无需修改分别记录。
- 版本化 Lookdev 文档、完整历史、源 GLB 引用、对象稳定身份、乐观版本冲突。已应用资产重开时恢复其图与参数，继续编辑生成下一份文档。
- 应用通过资产服务产生新 GLB 版本，场景入口只改指定实例的引用；预览灯光不会写入游戏灯光。应用使对应工作区试玩过期，更新作品继续使用既有候选构建流程。
- Shader 游戏输出由同一 TypeScript 编译器产生，按稳定对象及材质槽绑定；默认 RAF 游戏通过类型 AST 迁移到 WebGPU，串行完成绘制后再调度下一帧。依赖升级后重新准备匹配版本。
- PNG 截图；已保存版本的基础 PBR GLB、Shader ZIP、`.luma.zip` 经公共导出 API 登记制品并下载。GLB 不支持的效果明确提示。制作工具桥可读取、保存、提议、应用和导出，沿用当前任务工作区授权。

## 公共接口

- `POST /api/lookdev/{project_id}/documents`：预期版本保存。
- `GET /api/lookdev/{project_id}/documents`、`documents/{id}`：读取文档。
- `POST /api/lookdev/{project_id}/proposals`：固定目标、结构化操作、可取消。
- `GET .../turns`、`POST .../turns/{id}/finish`：主对话生命周期。
- `POST .../apply`、`GET .../bindings`：版本化应用及游戏绑定。
- `POST .../exports`、`GET .../exports/{id}/download`：已保存版本制品。
- 网络定义：`contracts/lookdev.openapi.json`；前端生成类型：`frontend/src/generated/lookdev-api.ts`。

后端固定 Node 入口仅处理结构化 JSON。Shader 语义与编译没有 Python 副本。

## Limitations

- 未执行真实在线模型的“同一对话生成并续改”验收；提供方链路测试使用明确的模拟响应。因此不能把整个五阶段验收声称为全部通过。
- 没有逐一进行所有旧模型/骨骼动画的浏览器回归；已完成构建、GLB 动画/贴图相关导出测试和真实静态 GLB GPU 验证。
- 非默认游戏若包含同步返回值依赖、构造器绘制、未知调度或 `setAnimationLoop` 等不安全自动迁移情况，会给出明确源码位置，需在主对话完成对应 WebGPU 工程修改。不会伪装成已兼容或降级 Shader。
- 全仓 TypeScript 检查仍有原有缺失测试/运行依赖与 Unity 页面类型问题；本次材质及主对话组合相关文件没有报错。
- 全仓模块生成的完整导入检查仍被原有动态测试导入和其他模块未声明依赖阻止。已使用现有生成 API 校验清单、依赖拓扑并刷新生成物，完整检查的失败记录保留，未修改或关闭检查器。
- 本次未发布或提交版本。宿主原有后端进程需重新启动才能加载新增 API。

材质面板提供“打开本地模型”（GLB / FBX）与“浏览 3D 库”。本地导入复用宿主 importProjectAssetFile 的检查和入库流程，成功后在原生标签打开新资产；原编辑器草稿保持。3D 库复用 10w 的 asset.builtin-library 面板。
