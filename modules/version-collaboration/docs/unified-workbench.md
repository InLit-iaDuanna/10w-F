# 统一应用编辑器

公开入口 `loadIntegratedWorkbench()` 返回接受 `@sceneops/core-ui.IntegratedWorkbenchProps` 的懒加载 React 编辑器。宿主负责项目空态、文档读取/保存、手动样例导入、AI 模型和建议、停靠布局。

支持自有版本对、变更、评论、理由与证据草稿。显式导入 Mock 后复用四层差异与追加式评论/决策面板，API和查询缓存均按项目隔离，对象选择同步宿主。自有仓库检视尚未自动接通，保存草稿不会调用Git、锁或回滚。

默认空项目不选择或运行 Demo。草稿通过 `onSave` 保存到当前项目的模块文档，错误可见且保留输入；`onDirtyChange` 支持切换项目提醒。旧独立入口保持兼容。

## 验证边界

本轮编辑器代理仅实现与静态阅读，未启动服务、运行测试、执行案例、构建、渲染或真实 AI。唯一启动/导入/空态烟测由主集成任务执行，结果见根交付记录；完整类型、业务流程与外部链路均未在此声明通过。

## 可视化版本树（2026-09-06）

UI 修订：布局读取版本编辑器自身宽度，窄分栏按单列树向下展开，宽区域按可用宽度排列分支。每个提交的分支标签预留独立行高，后续提交不会与之叠放。默认比例无需横向寻找根节点；「适应」恢复当前区域宽度及起点。提交详情与分支操作面板在底部展开，各自滚动，不覆盖画布。已在约 450px 右侧分栏目视验证，并通过 300/440/1000px 节点边界与不重叠最小测试。

统一版本页现在优先展示整个项目的纵向 Git 树，评审表单折叠在下方。项目作为根节点，提交使用 Git 的拓扑顺序与真实 parent OID，每个本地分支作为独立末端节点长在其真实 tip commit 上；多个分支指向同一提交时仍分别展开，但不会伪造额外提交。最多读取 200 次提交。支持分支历史高亮、拖动滚动、缩放、HEAD 定位及键盘选择节点。合并保留所有父节点连线；窗口外父节点不绘制虚构连线。

节点详情显示作者、时间、提交 ID、父提交和变更文件；合并文件以第一父提交比较。当前工作区显示待提交文件及冲突状态。进度来自宿主公开策划服务，显示真实阶段、正式版本数、计划卡片数与已登记卡片分支数；已确认策划提交标注里程碑，分支末端显示对应制作卡片标题，不将计划卡片当作已完成工作。暂无生产完成率数据。

`GET /api/version-collaboration/tree` 与 `GET /api/version-collaboration/tree/commits/{commit_id}/files` 使用项目请求头隔离。客户端不传目录或 Git argv；服务端校验登记根目录，清除继承的 Git 仓库重定向环境。尚无文件夹、尚无提交、Git 不可用和网络失败均显示错误及重试。

工具栏「分支」面板列出本地分支，并支持从当前或选中提交创建并切换分支、切换已有分支。每次操作先生成 typed BranchChangeSet dry-run，显示目标、起点和阻塞原因，用户再次点击「确认执行」后才调用固定 Git argv。HEAD 在预览后变化、工作区有未提交文件、存在冲突、名称非法、目标缺失或重名都会阻止执行。本增量不提供删除或合并分支。

验证：临时独立仓库的创建分支 dry-run → 确认 → 切换主路径通过；确定性分叉/合并布局主路径通过；Vite 成功转换新增 TSX。失败路径测试已补充。浏览器已确认真实分支列表与脏工作区阻塞提示；完整测试未运行。

## 项目进度总览（2026-09-08）

默认 ProjectOverview 聚合策划阶段、全部制作卡片（描述、验收、依赖、分支）与确认版本。宿主将公开 PlanningJourney 状态投影到 TreeProgress，不直接读取其他模块内部存储。新增 cards/versions 默认空元组，title 默认 null；网络类型由模块 generate_contracts.py 生成。版本提交、分支过滤、文件详情及分支预览确认仍由 VersionTree 承载。尚无执行证据的制作/验证/发布不标记完成。

视觉修订：总览采用嵌入式紧凑仪表盘，移除网页式主标题与宣传文案。版本历史使用按时间排列的提交列表，分支在对应提交旁标注，点击后显示文件详情；不再把分支末端画成容易误读的提交节点，也不再提供画布缩放。
