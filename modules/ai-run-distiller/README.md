# 模板沉淀与经验

公开 Python 包为 `sceneops_ai_distiller`。原有 `distill_run` 仍只把成功的、可沉淀的运行转换为流程模板；失败、撤回和人工纠正由独立的 `ExperienceService` 承载。没有新增 Agent 框架、向量数据库、模型训练或 Skill 写入。

经验服务由 API 组合根注入普通对话、策划旅程及卡片、类型化 Agent 和原生 Codex/CodeBuddy 请求。业务模块通过公开接口提供已保存的消息、动作、验证记录；服务不读取其内部表。默认开启经验读取与自动学习，两个开关独立，关闭不会删除记录。

## 使用

主对话工具栏的“经验”打开共享面板，可搜索当前项目及共享经验，查看适用条件、来源、证据性质和历史修订，编辑、停用、启用或恢复旧版本。恢复会创建新修订；并发更新返回版本冲突，保留用户草稿。弹窗沿用工作台的颜色、字体、按钮、焦点及返回交互，并适配窄窗口。重设计将经验库、学习动态和设置分开，默认阅读，按需编辑；主题及工具/类型/状态筛选见 [分类与调用说明](../../docs/experience-organization.md)。

回复与 Agent 时间线的“本次依据”记录对应请求实际提供的条目版本；记忆修订和学习结果显示在原消息下。策划使用精确回复 ID，不再以项目最近一次请求代替本次依据。提供、执行引用和验证分别记录；完整说明及验证边界见 [对话记忆](../../docs/conversation-memory.md)。

## 保存、召回与学习

复用工作台 SQLite 数据库。条目、修订、使用快照、来源游标、学习批次、复核检查点和调用账本分别保存，通过主键、唯一约束与事务避免重复提交。种子随 Python 安装包提供：26 条经验、51 个唯一证据引用；导入无需模型、幂等且不覆盖人工修订。历史测试只属于来源项目。

项目事实强制留在当前项目。共享条目只包含提炼的通用内容及必要的证据性质/来源引用；不附带其他项目原文。进入学习或保存的文本使用现有脱敏工具处理。读取共享经验不授予读取来源项目的权限。

召回使用 SQLite FTS5 trigram，标题、内容、适用条件、主题名称和领域标签参与排名。当前项目和共享范围先受服务端约束；停用、被替代条目不提供。调用者传入明确平台时排除不兼容项。相关反证随相应方法提供。最多 8 条，总序列化上下文不超过 12,000 字符；截断会明确标注。短于三个字符的独立词不会形成 trigram 查询。检索不调用模型。

只学习首次启用时间之后的新保存记录，不回溯工作台历史。前台结束后合并同项目材料，异步学习；无新增材料不调用模型。每批最多 2 次请求，第二次仅用于冲突复核；每日默认 20 次，按 Asia/Shanghai 日期计算并保留 UTC 时间。预算独立于制作授权，失败调用仍计数，未报告费用显示未知。复核等待跨天额度时保留第一次提案与原修订，重启后继续复核。批次固定提供方和模型，配置变化不会静默切换。

模型结果必须引用输入中已有的来源。模型自述、动作观察、构建/行为验证、用户陈述保留不同的证据性质；不明结果不升级为已验证修复。提交时再次检查学习开关及修订版本，防止后台覆盖人工修改。中断和失败保留材料及原因；可重试仍有批次余额的材料，已用尽批次调用数的失败材料保留供查看，不额外突破上限。

## 接口

所有路由继承工作台现有本地认证。项目归属由服务端核对。OpenAPI 与前端类型通过 `pnpm generate:experience` 从 Pydantic 导出，生成文件在 `contracts/experience.openapi.json` 和 Agent 前端 `generated/experience-api.ts`。

| 路由 | 用途 |
| --- | --- |
| `GET /api/experience/topics` | 获取六个主题的 ID、名称及说明 |
| `GET /api/experience/settings` | 读取开关、启用时间、预算 |
| `PUT /api/experience/settings` | 修改独立开关和预算 |
| `GET /api/experience/status` | 批次、待处理材料、当日消耗、失败原因 |
| `GET /api/experience/entries` | `project_id`、`q`、`scope`、`include_disabled` 筛选 |
| `GET /api/experience/entries/{id}` | 详情及来源证据 |
| `PATCH /api/experience/entries/{id}` | 带 `expected_revision` 编辑或切换启用状态 |
| `GET /api/experience/entries/{id}/revisions` | 查看修订历史 |
| `POST /api/experience/entries/{id}/restore` | 带 `expected_revision` 与目标 `revision` 恢复 |
| `POST /api/experience/learn` | 整理指定项目待处理的新材料 |
| `GET /api/experience/uses` | 按项目与 `use_key` 前缀查看实际提供版本 |

使用键包括 `message:{assistant_id}`、`journey:{project_id}:call:{id}`、`task:{task_id}:call:{call}`。这些键对应请求，不表示经验被采用或生效。

## 对话内记忆（2026-09-09）

`GET /project-memory` 聚合所属模块公开提供的决定引用与项目补充记忆；引用不复制为另一份事实。`set_memory_providers(source_resolver, project_reader, project_writer)` 在组合根连接来源核对与原模块修改接口。来源读取返回 `ExperienceSource`，引用读写使用 `ProjectMemoryReference`，写回可为异步方法。

`POST /memories` 接收已保存用户消息 ID、准确的 `origin_key`、内容和可选目标/预期修订；不接受客户端证据原文代替服务端来源。显式操作在关闭自动学习时仍可用。模型提案经 `apply_proposals` 校验原文引用，含糊候选仅生成 `pending` 事件，失败生成 `failed` 事件，不宣称已记住。前台提案不增加后台调用预算。

`GET /activity?project_id=&origin_key=` 返回准确关联的更新及学习批次；`POST /events/{id}/undo` 用预期修订生成新历史。创建记忆的撤销采用停用，保留出处。`GET /uses` 增加 `exact=true`，以请求键或来源键精确查看版本；旧前缀查询兼容保留。

`record_provided` 是所有调用方共用的实际提供快照接口：包含项目决定、无需关键词命中的补充项目记忆与选中经验，沿用 8 条及 12,000 字符上限。调用方必须把返回的实际快照放入模型请求；已记录请求不会因后续纠正改变。显式运行记录可以通过服务端 `record_usage_evidence` 关联被提供的条目版本与已保存动作/验证来源；这不是模型采用或验证通过的自动判断，也不向客户端开放伪造该记录的写入接口。

后台变更与来源 `origin_key` 同事务保存。停用条目的同名或相同来源重新创建被拒绝，保留用户停用决定。新增 `test_memory_conversation.py` 覆盖隔离临时库的保存、跨项目隔离、立即召回、纠正、精确快照、撤销、候选、冲突与重启；执行由主代理统一报告。

对话保存支持 `request_id`：同请求重试返回同一事件，内容变化返回冲突；未提供时按来源、回合、目标、预期版本与意图构造普通组合键。显式再次保存应使用新的请求 ID。前台 `apply_proposals` 必须由业务模块传入当前回合的 `allowed_source_ids`，模型不能自行扩大来源范围。共享经验的自动前台纠正仅保存候选，通用化修订仍经过后台提炼。候选保留 `proposal`，确认携带 `resolves_event_id`，原事件记录 `resolved_by` 以呈现处理结果。引用记录保留来源 `evidence_status`，未知验证记录不显示为通过。

记忆读取的预期业务、数据库或数据校验失败，通过 `unavailable_context` 返回空提供记录及 `failure_reason`，不把部分读取当作完整依据。能写入时保存失败快照；数据库不可写时 `persisted=false`，不宣称历史记录已保存。前台提案遇到数据库故障同样返回失败事件，失败事件本身无法保存时明确标注 `persisted=false`。此边界不吞掉任意程序异常；所属模块异常由组合适配器转为公开业务错误。

统一提供接口还按现有证据 ID 关联算法补入对应反证。方法与尚未提供的关联反证组成同一组，合计计入 8 项和 12,000 字符；无法同时提供时整组略去并标记截断，不能仅留下方法而遗漏已知反证。正文节选明确标记，来源及证据等级保持原样。
