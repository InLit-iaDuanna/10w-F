# Forge Shell Module Rules

## Ownership

This module owns typed workbench contracts, drawer interaction, editor/workspace registries, command and event buses, context binding, layout coordination, persistence, migrations, deterministic fixtures, and shell tests.

It does not own feature-editor components, domain data, external integrations, the generated module catalog, or the application bootstrap.

## Invariants

- `dockview-react` is the only docking engine. Shell state may coordinate Dockview but must not calculate pane geometry.
- Home contains only `assistant.conversation`; every edge starts hidden.
- Assistant layout changes that materially alter a customized workspace require confirmation.
- Layout state stays separate from domain/server state.
- Heavy and render-capable editors load lazily; hidden render-capable instances receive suspension signals.
- Fixtures and tests identify deterministic editor contributions as `mock`. Executed unit tests are `live`.

## Commands

From `modules/forge-shell/frontend`, the available commands are:

```text
pnpm run typecheck
pnpm test
pnpm run test:bridge
```

Do not run these suites unless the current conversation explicitly authorizes them. The standing authorization permits only an import/startup smoke check and one minimal main-path smoke check.

## Generated files

`frontend/src/generated/module-manifest.ts` is generated by module-runtime. Application catalogs must be generated by the composition root; do not hand-edit generated catalogs from this module.

## Acceptance

Keep full module and browser suites ready to run. Mark them `pending approval` when the current testing authorization does not permit execution.
